# API設計書

本書ではAPIを機能単位で分類し、各APIを以下の8項目で定義する。
各項目の記入用凡例は、実際の仕様を記入した時点で削除する。

## 共通凡例

**1. 概要**

- APIの目的と実現する機能を記載する。
- 対応するシステム要求仕様IDを記載する。

**2. エンドポイント**

- HTTPメソッド（GET、POST、PUT、PATCH、DELETE等）を記載する。
- リクエスト先のURLパスを記載する。

**3. 認証・認可**

- 認証の要否を記載する。
- 利用可能なロールと操作権限を記載する。
- 対象データの所有者・所属関係など、追加の認可条件を記載する。

**4. リクエスト**

- パスパラメータ、クエリパラメータ、リクエストボディを定義する。
- 各項目の名称、データ型、必須・任意、入力制約を記載する。
- ページング、検索、ソートなどの指定方法を必要に応じて記載する。
- 入力項目が存在しない場合は「なし」と記載する。

**5. レスポンス**

- 正常終了時のHTTPステータスコードを記載する。
- レスポンスボディの項目名、データ型、返却内容を定義する。
- 必要に応じてJSON形式のレスポンス例を記載する。
- レスポンスボディが存在しない場合は「なし」と記載する。

**6. エラー**

- エラーの発生条件を記載する。
- 対応するHTTPステータスコードとエラーコードを記載する。
- API固有のエラーを定義し、共通エラー仕様と重複する記述は省略する。

**7. 処理仕様**

- APIが実行する業務処理の流れを記載する。
- 参照・更新するデータと処理条件を記載する。
- 状態遷移、整合性、排他制御、トランザクションの要件を必要に応じて記載する。
- 処理失敗時のロールバックなど、必要な動作を記載する。

**8. 関連仕様**

- 関連する要求仕様ID、ユースケースIDを記載する。
- 参照すべき業務ルール、状態遷移仕様、データ設計などを記載する。
- 関連するAPIがある場合は、そのAPI IDを記載する。
- 関連仕様がない場合は「なし」と記載する。
