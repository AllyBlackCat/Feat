# システム要求仕様書

## 1. 文書目的
本書は、顧客要求仕様書および要求分析成果物に基づき、
本システムが満たすべき機能要求、非機能要求および制約事項を定義することを目的とする。

本書の上位・関連文書は以下のとおりである。
- 顧客要求仕様書
- 用語・業務概念定義書
- 業務ルール一覧
- 状態遷移仕様書
- 権限マトリクス
- ユースケース仕様書

## 2. システム概要
本システムは、プロジェクトおよびタスクの情報を一元管理し、担当者、進捗、期限、レビュー、コメント、
変更履歴等の業務情報を共有・管理するためのWebアプリケーションである。

利用者は、プロジェクトやタスクの状況を確認し、タスクの作業開始、レビュー依頼、承認、差し戻し等の
業務をシステム上で行う。

## 3. 対象範囲
本システムの対象範囲は以下のとおりとする。
1. 認証
    - ログイン
    - ログアウト
    - パスワード変更
    - パスワード再設定
    - ログインセッション管理

2. ユーザー管理
    - ユーザー登録
    - ユーザー情報変更
    - ユーザー利用停止
    - システム管理者管理

3. プロジェクト管理
    - プロジェクト管理
    - プロジェクトメンバー管理
    - プロジェクト管理者管理
    - プロジェクト進捗確認

4. タスク管理
    - タスク管理
    - タスク担当者管理
    - レビュアー管理
    - タスク進捗管理
    - タスクレビュー
    - タスク承認・差し戻し
    - タスクコメント
    - タスク変更履歴管理
    - タスク検索
    - 個人タスク管理

なお、バージョン1.0のリリース時点の対象外については、顧客要求仕様書「20.初期リリース対象外」に従う。

## 4. システム利用者

1. 一般メンバー
    - 許可されたプロジェクトに対して許可された業務を実行する権限を持つユーザー
    - 対象プロジェクトの担当タスクを実行する権限を持つ
    - 対象プロジェクトのレビュー担当タスクをレビューする権限を持つ

2. プロジェクト管理者
    - プロジェクトを管理する権限を付与されたユーザー
    - 対象プロジェクトに対する管理権限を持つ

3. システム管理者
    - システムを管理する権限を付与されたユーザー
    - ユーザー管理を行う
    - すべてのプロジェクトを参照し、各機能で許可された管理操作を実行できる

詳細は権限マトリクス参照。

## 5. 機能要求
### 5.1 認証
#### SR-AUTHENTICATION-001　ログイン
1. 認証方法
    - ユーザーはメールアドレスとパスワードを入力してログインできること
2. 利用停止判定
    - ユーザーが利用停止状態にあるかを判定し、利用停止状態の場合はログインできないこと
3. ログイン成功
    - ユーザーが認証に成功した場合、ログイン状態とすること
    - ユーザーが認証に成功した場合、失敗回数を0にすること
4. 認証失敗
    - ユーザーが入力したメールアドレスとパスワードの組み合わせが不正である場合、ログインできないこと
    - 失敗回数はカウントされること。
5. ログイン認証に5回連続で失敗した場合のログイン制限
    - カウントした失敗回数が5回に到達した場合、ユーザーはその時点から15分間ログインできないこと
    - ログイン制限の発動中にユーザーがログインを試行した場合でも、ログイン制限時間は延長しないこと
6. 認証失敗回数のリセット
    - ユーザーの操作がないまま15分間が経過した場合、失敗回数を0回にすること
    - ログイン制限の発動から15分が経過した場合、失敗回数を0回にすること
7. 汎用エラーメッセージの表示
    - 利用停止、認証失敗、ログイン制限によってログインできない場合、汎用エラーメッセージのみを返却すること
