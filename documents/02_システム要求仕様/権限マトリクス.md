# 権限マトリクス

## 1. 本書の目的

本書は、本システムにおけるユーザーごとの操作権限を整理する。

各機能について、どの利用者がどの操作を実行できるか、および実行時の条件を定義する。

## 2. 対象ロール

本システムでは以下のロールを定義する。

| ロール | 概要 |
| --- | --- |
| 一般メンバー | - |
| プロジェクト管理者 | - |
| システム管理者 | - |

## 3. 権限マトリクス

○：当該ロールに操作権限がある
△：本人・担当者・指定レビュアー等の権限上の条件を満たす場合のみ操作可能
×：当該ロールに操作権限がない

なお、○または△の場合でも、状態遷移条件、プロジェクトステータス、タスクステータスおよび業務ルールによる制約を受ける。
完了または中止したプロジェクトはシステム管理者を含め参照専用とし、プロジェクト配下の業務データを変更する操作は行えない。

## 4. 条件付き権限

### AUTH-003
- 一般メンバーが編集できるのは、自身が担当するタスクのタイトルおよび内容のみ。
- 完了タスクおよび無効化タスクは編集できない。
- 完了または中止したプロジェクトに属するタスクは編集できない。

### AUTH-004
- 一般メンバーは、自身が担当者である場合のみ作業開始できる。
- プロジェクト管理者は、自身が担当者である場合のみ作業開始できる。
- 作業開始は所属プロジェクトが「進行中」であり、対象タスクが無効化されていない場合に限る。

### AUTH-005
- 一般メンバーは、自身が担当者である場合のみレビュー依頼できる。
- プロジェクト管理者は、自身が担当者である場合のみレビュー依頼できる。
- レビュー依頼は所属プロジェクトが「進行中」であり、対象タスクが無効化されていない場合に限る。

### AUTH-006
- 一般メンバーは、自身がレビュアーである場合のみレビューを実行できる。
- プロジェクト管理者は、自身がレビュアーである場合のみレビューを実行できる。
- レビュー開始は所属プロジェクトが「進行中」であり、対象タスクが無効化されていない場合に限る。

### AUTH-007
- 一般メンバーが承認・差し戻しを実行可能なのはレビュアーである場合のみ。
- プロジェクト管理者が承認・差し戻しを実行可能なのはレビュアーである場合のみ。
- 承認・差し戻しは所属プロジェクトが「進行中」であり、対象タスクが無効化されていない場合に限る。

### AUTH-009
- コメント編集は自身の未削除コメントに限る。
- 完了または中止したプロジェクトに属するコメント、および無効化タスクに属するコメントは編集できない。

### AUTH-010
- 一般メンバーおよびプロジェクト管理者が削除できるのは自身の未削除コメントに限る。
- システム管理者は他の利用者の未削除コメントも削除できる。
- 完了または中止したプロジェクトに属するコメント、および無効化タスクに属するコメントは削除できない。
