# 状態遷移仕様書

## 1. 本書の目的

本書は、システム上で状態を持つ業務概念について、状態の種類、状態遷移および遷移条件を定義する。

本書では以下を対象とする。

- タスクステータス
- プロジェクトステータス

## 3. タスク状態遷移

### 3.1 タスクステータス

タスクは以下の状態を持つ。
タスクの作成時のステータスは「未着手」で固定とする。

| 状態 | 概要 |
| --- | --- |
| 未着手 | 作業開始前の状態 |
| 作業中 | 担当者が作業している状態 |
| レビュー依頼 | レビュアーへレビューを依頼している状態 |
| レビュー中 | レビュアーがレビューしている状態 |
| 差し戻し | レビューにより再対応が必要となった状態 |
| 完了 | タスクが完了した状態 |

---

### 3.2 基本状態遷移

| 現在状態 | 操作 | 遷移先 | 遷移条件 | 備考 |
| --- | --- | ---| --- | ---|
| 未着手 | 作業開始 | 作業中 | 担当者が設定されていること | - |
| 作業中 | レビュー依頼 | レビュー依頼 | レビュアーが設定されていること | - |
| レビュー依頼 | レビュー開始 | レビュー中 | - | - |
| レビュー中 | 承認 | 完了 | - | - |
| レビュー中 | 差し戻し | 差し戻し | 差し戻し理由が入力されていること | - |
| 差し戻し | 再対応開始 | 作業中 | 担当者が設定されていること | - |
| 完了 | 再オープン | 作業中 | - | 再オープン履歴を記録する |

### 3.3 特殊な状態遷移

#### レビュー中のレビュアー変更

「レビュー中」のタスクでレビュアーを変更した場合、タスクステータスを「レビュー依頼」に戻す。

| 現在状態 | 操作 | 遷移先 | 条件 |
| --- | --- | ---| --- |
| レビュー中 | レビュアー変更 | レビュー依頼 | 新しいレビュアーが設定されていること |

---

### 3.4 状態遷移に伴う制約

- 「作業中」に遷移するためには担当者が設定されていなければならない。
- 「レビュー依頼」に遷移するためにはレビュアーが設定されていなければならない。
- 担当者とレビュアーは同一ユーザーにできない。
- 完了状態では担当者・レビュアーを変更できない。
- 完了タスクの担当者・レビュアーを変更する場合は、先に再オープンする。
- 状態変更は変更履歴へ記録する。

## 4. プロジェクト状態遷移

### 4.1 プロジェクトステータス

プロジェクトの作成時のステータスは「準備中」で固定とする。

| 状態 | 概要 |
| --- | --- |
| 準備中 | プロジェクト開始前の状態 |
| 進行中 | プロジェクトを実施している状態 |
| 完了 | プロジェクトが完了した状態 |
| 中止 | プロジェクトを中止した状態 |

---

### 4.2 プロジェクト状態遷移

| 現在状態 | 操作 | 遷移先 | 遷移条件 | 備考 |
| --- | --- | ---| --- | ---|
| 準備中 | 開始 | 進行中 | プロジェクト管理者が1名以上設定されていること<br>プロジェクトメンバーが1名以上存在すること<br>顧客要求仕様書 FR-PROJ-001 に定めるプロジェクト情報が設定されていること | - |
| 準備中 | 中止 | 中止 | 追加条件なし | - |
| 進行中 | 中止 | 中止 | 追加条件なし | - |
| 進行中 | 完了 | 完了 | 未完了タスクが存在しないこと | - |

---

### 4.3 完了・中止後の扱い

- 完了または中止したプロジェクトは原則として参照専用とする。
- 通常の編集操作は行えない。
- システム管理者による管理上必要な操作は例外とする。
- 完了および中止は終端状態とし、他のプロジェクトステータスへ遷移できない。

---

## 5. 禁止される状態遷移

以下のような、定義されていない状態遷移は許可しない。

例：

- 未着手 → 完了
- 作業中 → 完了
- レビュー依頼 → 完了
- 完了 → レビュー中
- 準備中 → 完了
- 完了 → 進行中
- 中止 → 進行中

システムは定義されていない状態遷移を拒否する。
